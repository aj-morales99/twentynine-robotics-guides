# FullVision code library

## Start here

<div class="do-dont">
  <div><h3>Do</h3><ul><li>Call <code>fullVisionInit()</code> once from <code>setup()</code>.</li><li>Stop motors before waiting or changing control mode.</li><li>Refresh sensor values before making a decision.</li><li>Keep speeds within the tested 0–100 range.</li></ul></div>
  <div><h3>Don't</h3><ul><li>Do not call interrupt handlers yourself.</li><li>Do not run Bluetooth serial and RC pulse interrupts on the same shared pins at once.</li><li>Do not edit the installed library without recording the version and change.</li><li>Do not test new movement code with the blade or wheels touching a surface.</li></ul></div>
</div>

<div class="function-list">
  <section class="function-card"><h3><code>fullVisionInit()</code></h3><p class="function-meta">Setup · call once · returns nothing</p><p>Initializes the buttons, Serial1, Bluetooth serial, I²C OLED, ADC, PWM, motor pins, sensor pins, and flag servo.</p><pre><code>void setup() {
  fullVisionInit();
}</code></pre><p class="function-output"><strong>Expected result:</strong> the hardware is ready for the menu and the flag moves to its default raised position. The function does not print a success message.</p><p><strong>Do:</strong> call it once. <strong>Don't:</strong> call it repeatedly inside <code>loop()</code>.</p></section>
  <section class="function-card"><h3><code>textDisplay(text1, size1, text2, size2, text3, size3)</code></h3><p class="function-meta">OLED display · lines 2 and 3 are optional · returns nothing</p><p>Clears the 128 × 32 OLED, centers as many as three supplied text lines, and displays them using their matching text sizes.</p><pre><code>textDisplay("MODE 1", 2, "PRESS SW2", 1);</code></pre><p class="function-output"><strong>Example OLED output:</strong><br><code>MODE 1</code><br><code>PRESS SW2</code></p><p><strong>Do:</strong> keep messages brief. <strong>Don't:</strong> update continuously when the text has not changed.</p></section>
  <section class="function-card"><h3><code>readDistance(sensorPin)</code></h3><p class="function-meta">Enemy sensor · returns a distance in centimeters</p><p>Reads one supported analog Sharp GP2Y0A21 distance sensor, converts its voltage to centimeters, and clamps the result to 10–80 cm.</p><pre><code>float frontCm = readDistance(FRONT_PIN);</code></pre><p class="function-output"><strong>Example result:</strong> <code>frontCm</code> may become <code>28.4</code> when a target produces that calculated reading. Values outside the supported range are returned as 10 or 80.</p><p><strong>Do:</strong> compare readings using the same target and conditions. <strong>Don't:</strong> treat it as precision measurement outside its tested range.</p></section>
  <section class="function-card"><h3><code>readLine(sensorPin)</code></h3><p class="function-meta">Line sensor · declared but not implemented in the reviewed source</p><p>The header declares this percentage-returning helper, but the matching reviewed <code>.cpp</code> does not define it.</p><pre><code>// Use the implemented function instead:
lineDetection();
bool leftBoundary = LINE1;</code></pre><p class="function-output"><strong>Expected result if called directly:</strong> no valid runtime output; the sketch may fail to link because the function has no definition.</p><p><strong>Do:</strong> use <code>lineDetection()</code>. <strong>Don't:</strong> call <code>readLine()</code> until an implementation is added and verified.</p></section>
  <section class="function-card"><h3><code>readChannel(pulseValue, minLimit, maxLimit, defaultValue)</code></h3><p class="function-meta">RC input · returns a mapped integer</p><p>Maps a captured receiver pulse to the requested output limits. It applies a 1475–1525 µs neutral deadband and returns the default for pulses outside 800–2200 µs.</p><pre><code>int steering = readChannel(ch1_pulse, -100, 100, 0);</code></pre><p class="function-output"><strong>Example results:</strong> 1000 µs → <code>-100</code>, approximately 1500 µs → <code>0</code>, and 2000 µs → <code>100</code>.</p><p><strong>Do:</strong> establish neutral before enabling movement. <strong>Don't:</strong> pass a channel number; pass the captured pulse value.</p></section>
  <section class="function-card"><h3><code>setupInterrupts()</code></h3><p class="function-meta">RC input · setup · returns nothing</p><p>Configures PA8 and PB15 as pull-up inputs and attaches the interrupt handlers used to measure RC receiver pulses.</p><pre><code>Bluetooth.end();
setupInterrupts();</code></pre><p class="function-output"><strong>Expected result:</strong> receiver pulse widths begin updating <code>ch1_pulse</code> and <code>ch2_pulse</code>; there is no display output.</p><p><strong>Do:</strong> stop Bluetooth use first. <strong>Don't:</strong> attach RC capture while Bluetooth is active on the same pins.</p></section>
  <section class="function-card"><h3><code>stopInterrupts()</code></h3><p class="function-meta">RC input · cleanup · returns nothing</p><p>Detaches the RC pulse interrupts, restores PA8/PB15 as standard inputs, and resets both stored channel pulses to 1500 µs.</p><pre><code>stopInterrupts();
motorSTOP();</code></pre><p class="function-output"><strong>Expected result:</strong> RC pulse capture stops and both stored channel values return to neutral.</p><p><strong>Do:</strong> stop motors during a control-source change. <strong>Don't:</strong> assume detaching interrupts alone physically removes power.</p></section>
  <section class="function-card"><h3><code>modeDisplay(number)</code></h3><p class="function-meta">Menu and mode display · returns nothing</p><p>Reads the MODE switch and updates the OLED for the supplied selection number.</p><pre><code>modeDisplay(1);</code></pre><p class="function-output"><strong>Example output:</strong> AUTO side → <code>Mode 1</code>; RC/RMT side → <code>BT MODE</code>.</p><p><strong>Do:</strong> preserve its button and display expectations when customizing menus. <strong>Don't:</strong> confuse a displayed mode number with sensor-system count.</p></section>
  <section class="function-card"><h3><code>enemyDetection()</code></h3><p class="function-meta">Enemy sensors · refreshes global distance variables</p><p>Reads three or five enemy sensors according to <code>SYSTEM</code>. It updates <code>fLeftDist</code>, <code>frontDist</code>, and <code>fRightDist</code>, plus <code>leftDist</code> and <code>rightDist</code> for a 5-system build.</p><pre><code>enemyDetection();
if (frontDist &lt;= attackDist) motorFWD(attackSpeed);</code></pre><p class="function-output"><strong>Example result:</strong> a centered target could update <code>frontDist</code> to <code>22</code> while the two angled readings remain higher.</p><p><strong>Do:</strong> call it before a decision that needs current distances. <strong>Don't:</strong> configure five sensors on a robot that only has three.</p></section>
  <section class="function-card"><h3><code>lineDetection()</code></h3><p class="function-meta">Line sensors · refreshes <code>LINE1</code> and <code>LINE2</code></p><p>Compares each line sensor with its matching potentiometer threshold.</p><pre><code>lineDetection();
if (LINE1 || LINE2) motorREV(revSpeed);</code></pre><p class="function-output"><strong>Example result:</strong> left sensor on the white boundary → <code>LINE1 = true</code>; right sensor on the dark arena → <code>LINE2 = false</code>.</p><p><strong>Do:</strong> calibrate first. <strong>Don't:</strong> ignore boundary detection while increasing speed.</p></section>
  <section class="function-card"><h3><code>motorSTOP()</code></h3><p class="function-meta">Movement · stop · returns nothing</p><p>Writes zero to both direction inputs of both drive motors.</p><pre><code>motorSTOP();</code></pre><p class="function-output"><strong>Expected physical output:</strong> both drive motors stop receiving a movement command.</p><p><strong>Do:</strong> use it before menus and fault handling. <strong>Don't:</strong> treat software stop as a substitute for disconnecting power during mechanical work.</p></section>
  <section class="function-card"><h3><code>motorFWD(percentage)</code></h3><p class="function-meta">Movement · forward · 0–100%</p><p>Drives both motors forward at the requested percentage. Values above 100 are limited to 100.</p><pre><code>motorFWD(30);</code></pre><p class="function-output"><strong>Expected physical output:</strong> both wheels drive the robot forward at approximately a 30% PWM command.</p><p><strong>Do:</strong> begin at a low tested value. <strong>Don't:</strong> test with the wheels touching a surface until direction is verified.</p></section>
  <section class="function-card"><h3><code>motorREV(percentage)</code></h3><p class="function-meta">Movement · reverse · 0–100%</p><p>Drives both motors in reverse at the requested percentage.</p><pre><code>motorREV(30);</code></pre><p class="function-output"><strong>Expected physical output:</strong> both wheels drive the robot backward at approximately a 30% PWM command.</p><p><strong>Do:</strong> check rear clearance. <strong>Don't:</strong> reverse blindly after a line event without timing limits.</p></section>
  <section class="function-card"><h3><code>motorSLEFT(percentage)</code></h3><p class="function-meta">Movement · spin left · 0–100%</p><p>Drives the two sides in opposite directions to spin left.</p><pre><code>motorSLEFT(25);</code></pre><p class="function-output"><strong>Expected physical output:</strong> the robot rotates counterclockwise in place, subject to its motor wiring and orientation.</p><p><strong>Do:</strong> test direction on a stand. <strong>Don't:</strong> assume direction after hardware changes.</p></section>
  <section class="function-card"><h3><code>motorSRIGHT(percentage)</code></h3><p class="function-meta">Movement · spin right · 0–100%</p><p>Drives the two sides in opposite directions to spin right.</p><pre><code>motorSRIGHT(25);</code></pre><p class="function-output"><strong>Expected physical output:</strong> the robot rotates clockwise in place, subject to its motor wiring and orientation.</p><p><strong>Do:</strong> test direction on a stand. <strong>Don't:</strong> start at full speed.</p></section>
  <section class="function-card"><h3><code>leftMotorControl(pwm1, pwm2)</code></h3><p class="function-meta">Movement · advanced · each input 0–100</p><p>Controls the two direction inputs of the left motor directly.</p><pre><code>leftMotorControl(40, 0);</code></pre><p class="function-output"><strong>Expected physical output:</strong> the left motor runs in one direction at a 40% command while its opposite input remains off. Physical forward/reverse depends on the installed wiring.</p><p><strong>Do:</strong> keep one direction at zero in normal use. <strong>Don't:</strong> drive both directions at once.</p></section>
  <section class="function-card"><h3><code>rightMotorControl(pwm1, pwm2)</code></h3><p class="function-meta">Movement · advanced · each input 0–100</p><p>Controls the two direction inputs of the right motor directly.</p><pre><code>rightMotorControl(40, 0);</code></pre><p class="function-output"><strong>Expected physical output:</strong> the right motor runs in one direction at a 40% command while its opposite input remains off. Physical forward/reverse depends on the installed wiring.</p><p><strong>Do:</strong> keep one direction at zero in normal use. <strong>Don't:</strong> change only one side without understanding the resulting turn.</p></section>
  <section class="function-card"><h3><code>servoFlag(value)</code></h3><p class="function-meta">Servo output · returns nothing</p><p>Moves the flag servo and updates <code>flagDown</code>. A nonzero value writes 0° and marks the flag down; zero writes 100° and marks it up.</p><pre><code>servoFlag(1);  // flag down
servoFlag(0);  // flag up</code></pre><p class="function-output"><strong>Expected physical output:</strong> the flag moves between the two positions used by the firmware.</p><p><strong>Do:</strong> use the verified mechanism. <strong>Don't:</strong> force the servo against a mechanical stop.</p></section>
  <section class="function-card"><h3><code>exitMode()</code></h3><p class="function-meta">Mode control · returns nothing</p><p>Checks for SW1 and SW2 together. It clears the active BT, RC, AUTO, or CAL flag and then stops both motors.</p><pre><code>while (AUTOMode) {
  exitMode();
  // active behavior
}</code></pre><p class="function-output"><strong>Expected result:</strong> pressing SW1 and SW2 together exits the active loop and stops the drive motors.</p><p><strong>Do:</strong> keep this near the beginning of every active-mode loop. <strong>Don't:</strong> remove the user's safe exit path.</p></section>
  <section class="function-card"><h3><code>handlePA8()</code> / <code>handlePB15()</code></h3><p class="function-meta">Internal interrupt handlers · do not call directly</p><p>Measure rising-to-falling pulse time on the pins shared with Bluetooth. They update the two stored RC pulse values.</p><p class="function-output"><strong>Expected result:</strong> each valid receiver pulse updates its stored width in microseconds; there is no OLED or Serial output.</p><p><strong>Do:</strong> leave them to the interrupt system. <strong>Don't:</strong> call them from <code>loop()</code> or add display, serial, or delay work inside them.</p></section>

  <section class="function-card"><h3><code>setup()</code></h3><p class="function-meta">Arduino sketch entry point · runs once</p><p>The supplied sketch calls <code>fullVisionInit()</code> and then <code>motorSTOP()</code>.</p><pre><code>void setup() {
  fullVisionInit();
  motorSTOP();
}</code></pre><p class="function-output"><strong>Expected result:</strong> the board hardware initializes once and the motors begin in a stopped state.</p><p><strong>Do:</strong> keep initialization here. <strong>Don't:</strong> rename this Arduino entry point.</p></section>
  <section class="function-card"><h3><code>loop()</code></h3><p class="function-meta">Arduino sketch entry point · repeats continuously</p><p>Runs the Mini Hunter menu and the selected BT, RC, AUTO, or CAL control loop.</p><pre><code>void loop() {
  // menu and active-mode logic
}</code></pre><p class="function-output"><strong>Expected result:</strong> the OLED menu responds to MODE, SW1, and SW2, then the selected control behavior runs.</p><p><strong>Do:</strong> preserve a path back to the menu. <strong>Don't:</strong> rename it during normal robot use.</p></section>
  <section class="function-card"><h3><code>MODE_5()</code> / <code>MODE_6()</code></h3><p class="function-meta">Sketch functions · opening swerve maneuvers</p><p>Mode 5 spins left and curves from the left; Mode 6 mirrors the move to the right. The supplied sketch calls either once, then changes <code>modeSelected</code> to Mode 1.</p><pre><code>MODE_5();  // left opening swerve
MODE_6();  // right opening swerve</code></pre><p class="function-output"><strong>Expected physical output:</strong> a short 75 ms spin followed by an approximately 550 ms curved drive, then normal Mode 1 behavior.</p><p><strong>Do:</strong> tune on the actual arena at safe speed. <strong>Don't:</strong> assume the same delay traces the same path on every surface.</p></section>
  <section class="function-card"><h3><code>RCSumoBot()</code></h3><p class="function-meta">Sketch function · Bluetooth joystick control</p><p>Parses Bluetooth control messages, selects 40/70/100% speed levels, mixes forward and turn values, applies a dead zone, and sends commands to both motors.</p><pre><code>while (BTMode) {
  exitMode();
  RCSumoBot();
}</code></pre><p class="function-output"><strong>Expected result:</strong> joystick messages move the two motors; centered values stop them; <code>RC_OFF</code> stops the motors and leaves BT Mode.</p><p><strong>Do:</strong> use the matching V2.6 Bluetooth panel. <strong>Don't:</strong> remove the stop command or bounds checks.</p></section>
  <section class="function-card"><h3><code>test()</code></h3><p class="function-meta">Sketch service function · not called automatically</p><p>Passes lines from Serial1 to the Bluetooth module and returns the module's response to Serial1. It is intended for Bluetooth-module configuration.</p><pre><code>// Temporary service only:
// rename normal loop() to loopp()
// rename test() to loop()</code></pre><p class="function-output"><strong>Expected result:</strong> commands entered through Serial1 are sent to the Bluetooth module and its reply appears in the serial output.</p><p><strong>Do:</strong> back up the sketch and restore the original names afterward. <strong>Don't:</strong> leave the service routine as <code>loop()</code> for normal robot operation.</p></section>
</div>
